# paper-polish：让编辑一眼看到新意，又不过度宣称

## 这个 skill 针对的问题

AI 润色论文时有两种方向相反的失败。

1. **防御性写作（主要问题）。** 典型表现：限定语层层叠加；单独成句的 "we do not claim / this does not imply"；先让步、后给结果；主结果埋在摘要第 7 句，还是以公式形式给出；6 条等权重的贡献清单；缺口写成 "well known anecdotally"，不点名前人；大段交代版本历史。编辑读完前两页，仍说不出"新结果是什么、为什么重要"，于是 desk reject。
2. **反向过冲。** 被要求"写得更有力"时，又把条件结果写成无条件结果、把数值证据写成定理、把相关写成因果，滥用 law / first / universal / optimal / significant，或者用一个没点名的稻草人基线算出的倍数做头条。外审会抓住这些。

本 skill 的目标是**校准**：每条主张用证据允许的最强措辞说一次，适用范围在结果句里正面交代一次。不是删掉限定，而是把限定放到该放的位置，说具体。

依据的真实案例见 `references/case-studies.md`：一篇稿子两次被编辑以 "lack of clarity" 拒稿；另一篇的模拟审稿同时批评了 caveat 过多和 overclaim。这两个案例都来自量子信息领域，但所说明的模式是跨学科的。**所有"好不好"的标准都以目标期刊同体裁的范文为准，而不以任何一个领域的习惯为准。**例如医学期刊要求结构化摘要，观察性研究必须用关联而非因果的措辞，这些都是该领域的规范，不是防御。

## 硬性规则

1. **不动原稿。** 所有产出都写到稿件所在目录的 `polish/<YYYY-MM-DD>/` 下。如果是 git 仓库，先看 `.git/info/exclude` 和 `.gitignore`，把 `polish/` 加进 `.git/info/exclude`（只在本地生效，可以撤销），并告诉用户。仓库的 CLAUDE.md 或 memory 规定稿件冻结、公开仓库不能提交内部材料的，照规定执行。
2. **不改数学，不改数据，不新增结论。** 新文本里的每个数字都要在 notes 里写明出处（`file:line` 或数据文件），并重新核对过。
3. **范文必须真实。** 每篇都要有经 `scripts/exemplar_meta.py` 解析过的 DOI、arXiv ID 或 PMID。不能凭记忆列文献。卷号、页码、作者以 API 返回为准，用户自己的调研文件也要核对（曾查出 8 处错误）。
4. **模拟编辑和模拟审稿的结论一律标"推断"**，不能当成真实编辑的意见。
5. **区分表述问题和实质问题。** 表述问题靠重写能解决；实质问题需要新结果（例如主结论是标准方法的直接应用、效应量太小、样本或对照不足、基线是稻草人）。实质问题要如实告诉用户，不能用措辞去掩盖。
6. 与用户的对话用中文；论文文本用英文，或稿件原来的语言。
7. **你自己也会写得防御。** 重写之后必须跑扫描脚本，并对照 ledger 自查（Phase 6）。不要在新稿里加入稿件原本没有的免责句。

## 模式

| 模式 | 做什么 | 何时用 |
|---|---|---|
| `full`（默认） | Phase 0–7 | 第一次润色这篇稿子 |
| `survey` | Phase 0–4，只出调研报告 | 想先看差距、暂不改稿 |
| `rewrite` | 复用工作目录里已有的 `survey_report.md` 和 `exemplars/`，做 Phase 5–7 | 调研已做过 |
| `check` | 只做 Phase 1 的扫描和 Phase 7 的盲测 | 投稿前最后检查 |

用户没指定模式时，按 `full` 执行。

## Phase 0：接收

确定下面几件事。能从稿件和仓库推断的就不问，通常只有目标期刊需要问用户。

- **稿件入口文件**：`.tex`、`.docx`、`.md`、`.txt`，脚本都能直接读；PDF 需要本机装有 `pdftotext`，否则请用户导出 Word 或文本。有多个入口（预印本版、期刊版）时，问用哪一个。
- **目标期刊。** 它决定范文池和编辑标准，由用户决定。
- **体裁**：理论或数学结果；方法或算法；计算或模拟；实验（实验室实验、随机对照试验）；观察性研究（队列、病例对照、横断面、调查）；机器学习或数据驱动研究；定性研究；系统综述或元分析；综述或观点文章。体裁决定证据等级（见 `references/claim-calibration.md`），也决定应遵守的报告规范（例如 CONSORT、STROBE、PRISMA，以及期刊对结构化摘要的要求）。
- **已有材料**：拒稿信、审稿意见、用户自己的调研文件、以前做过的 survey。拒稿理由要原文引用进报告。
- **用户一句话的"新意"**（如果用户愿意给）。不给也没关系，Phase 5 会提炼出来请用户确认。

然后建立工作目录：`polish/<date>/`，内含 `exemplars/`。

## Phase 1：本文的"编辑视图"与基线测量

编辑决定是否送审之前，通常只读标题、摘要、引言的前一两页、图 1 及其图注，以及 cover letter。

1. 跑扫描：
   ```
   python3 <skill-dir>/scripts/hedge_scan.py <稿件 .tex/.docx/.md/.pdf> --json polish/<date>/scan_before.json > polish/<date>/scan_before.md
   ```
   脚本会给出摘要、引言、结论的指标（段落数、词数、句数、行内公式数、主结果首次出现在第几句或第几段、限定语、防御性句式命中及位置、因果措辞和 "significant" 的使用），以及图注长度，并标出结构化摘要。它只提供线索，最终判断要靠通读。
2. **建 claim ledger**（格式见 `references/claim-calibration.md`）。从摘要、引言、结论、cover letter 里列出每条主张，回到正文找支撑（定理编号、图表、统计分析、数据文件），记录证据类型和前提条件，判断当前措辞是偏弱、恰当还是偏强。
3. **通读并记录结构**：主结果第一次出现在摘要第几句，用文字还是公式；在引言第几段出现；贡献清单是什么形式；适用范围在文中出现几处，措辞是正面还是负面；图 1 图注有多长；有没有在定义之前就使用的术语。

## Phase 2：增广调研，找范文

完整做法见 `references/exemplar-protocol.md`，要点如下。

- **池 A，目标期刊范文。** 目标期刊或同档期刊近 5 年、同体裁、写得好的文章：高引用、编辑推荐（Editors' Suggestion、Editor's Choice 等）、获奖论文，或用户指定的。这是主力，取 15–30 篇，按体裁分 3–4 组。
- **池 B，最近邻工作。** 5–10 篇编辑和审稿人会拿来与本文比较的文章（同一问题或同一技术），不限期刊。用来写"点名前人的缺口"，也用来做新颖性审计：有没有前人已经做过的结果，有没有本文应该承认的标准技术。
- **池 C，编辑标准。** 目标期刊官方的 about、scope、criteria 页面，原文摘录。
- **检索。** 用 `exemplar_meta.py search`（基于 OpenAlex，覆盖各学科，可按期刊、年份过滤，按引用或相关度排序），换几组关键词多查几次，再配合 WebSearch、各领域的数据库（见 `references/exemplar-protocol.md`）和用户的调研文件。
- **核验并下载。**
  ```
  python3 -I <skill-dir>/scripts/exemplar_meta.py fetch <DOI / arXiv ID / PMID ...> --out polish/<date>/exemplars --intro
  ```
  每篇生成一个 `<slug>.md`（元数据、核验来源、摘要、引言），另存原始引言：来自 arXiv 源码的存为 `<slug>.intro.tex`，来自 PMC 开放获取全文的存为 `<slug>.intro.txt`。状态为 NOT FOUND 的不能用。
- **文本来源。** 摘要优先用出版社在 Crossref 存的版本。引言依次尝试：arXiv 源码（物理、数学、计算机等）；PMC 开放获取全文（生物医学、生命科学，以及许多开放获取期刊）；出版社的开放获取页面；用户提供的 PDF。读的是哪个版本都要记录下来。WebFetch 返回的是模型摘要，不是原文，不能用来做逐字引用或计量。
- 样本少于 8 篇时要如实说明，并相应降低结论的强度。
- 池 B 在这里只做轻量审计。需要正式的新颖性判定，或者调研发现"主结果可能是标准结果"时，转用 `novelty-audit`。

## Phase 3：逐篇拆解（并行）

- 按体裁分组，每组派一个子代理，在同一条消息里并发启动。每个子代理按 `references/exemplar-protocol.md` 里的分析卡模板，把每篇的卡片填进对应 `.md` 的 "Analysis card" 一节。
- **子代理只读范文，不读本文**，避免结论被本文带偏。
- 子代理返回后，在主会话里抽查 2–3 篇，核对卡片里的逐字引文与原文一致。
- 用同一口径计量全部范文：
  ```
  python3 <skill-dir>/scripts/hedge_scan.py polish/<date>/exemplars/*.md --summary > polish/<date>/exemplar_stats.md
  ```

## Phase 4：对比与诊断，写 `survey_report.md`

报告用中文写，结论放在最前面。用户点名的四个方面逐一对比。每个格子写清两件事：范文怎么做（举 1–2 篇，点名），本文怎么做（给行号）。数值给范文的中位数和范围。

1. **研究问题**：问法是什么，答案是什么形态（一个数或界、一个效应量、是或否、一个机制、一个方法），研究对象是什么，缺口有没有点名前人，结果的实际意义是什么（理论上约束了什么，或对临床、政策、工程、后续研究意味着什么）。
2. **写作行文**：句长、限定语密度、主动或被动、动词强度、公式和符号密度、图注长度、术语在首次出现前有没有解释。
3. **叙事重心**：一句话结论（slogan）、头条数字及其基线、新意落在哪里（结果、方法还是建模）、与前人的关系、适用范围怎样交代、篇幅怎样分配。
4. **摘要与引言**：指标见 `references/exemplar-protocol.md`。

此外还要写：

- **防御性句式诊断表**，列出类别、原句、行号、它为什么削弱新意、怎么改。类别定义见 `references/defensive-patterns.md`。
- **新颖性风险**（来自池 B）：前人已经做过的结果、本文用到的标准技术、应补引的文献。
- **优先级表**，三列：问题、只需重写、需要新结果。
- **可以套用的 2–4 个范文模板**：点名，并写出其摘要每一句的功能序列。
- **调研方法与局限**：样本只有成功发表的文章；计量口径；读的是哪个版本。

## Phase 5：Novelty spine（重写前唯一的确认点）

写出编辑在 30 秒内应该读到的 5 句话，每句给英文原文加中文说明，并标出对应的 ledger 条目：

1. **Result**：新结果是什么。用文字说，不用公式。
2. **Gap**：点名一篇前人工作，以及它缺的那一点。
3. **Stakes**：为什么重要，它约束了谁，或者改变了哪个可测量的量、哪项决策。
4. **Headline number**：最多一个，同一句里给出比较对象。比较对象必须是当前最好的方法、标准治疗、常用对照或生产环境默认设置，不能是自己搭的稻草人；实证研究要带上不确定性（置信区间等）。
5. **Scope**：一句话，正面措辞，附在结果上。

新意如何定位，是作者的决定。`full` 模式在这里停一次，请用户确认或修改 spine；用户明确说"不用确认"时才直接继续。

## Phase 6：重写

**产出**（全部写在工作目录里，不碰原稿）：

- `abstract_intro.tex`（或稿件原格式）：新的摘要和引言。可选附带标题候选 3–5 个、图 1 图注、结论段、cover letter。
- `polish_notes.md`，包含：
  - 结构对比表：原稿与新稿的段数、词数、主结果位置、限定语数等；
  - 每个数字的出处表（重新核对过）；
  - **"有意改动的说法（请作者确认）"**：凡是改变了主张的范围或强度、改了基线的命名方式、换了术语的地方，都列进来；
  - 本次没改、但并入正文时需要同步修改的地方（正文定义、图、编号等）；
  - 标题备选及理由。

**写作规则**（细则见 `references/defensive-patterns.md` 和 `references/claim-calibration.md`）：

- **摘要。** 格式先服从期刊规定，例如结构化摘要的标签和字数上限。在此之上，参照范文统计（`exemplar_stats.md`）决定句数、主结果出现的位置和符号密度。跨学科都成立的原则有：结果尽早出现，用文字说；头条数字最多一个，并写明比较对象；适用范围附在结果句里；结尾落在意义上，不落在局限上。Case A 中 26 篇物理期刊范文的统计（1 段、主结果在第 2–4 句、符号不超过 3 个）只是一个领域的例子，不能当作默认值。
- **引言。**
  - 第 1 段讲领域问题或现实动机，不写 "X is not only a Y" 这类定义式开头。
  - 第 2–3 段写缺口，点名前人。
  - 主结果在前 4 段内出现。
  - 贡献怎么写看范文惯例：多数期刊用散文写 2–3 个；有些领域（例如计算机会议）习惯在引言末尾列出贡献，那就照列，但仍要有主次，不能 6 条等权重。
  - 适用范围写成一段，正面措辞。
  - 不写版本历史；那属于预印本平台的版本说明或 cover letter。
- **动词强度由证据决定**，按 ledger 的证据等级选（见 `references/claim-calibration.md`）：prove / show / establish；find / observe / measure；is associated with（观察性研究）；conjecture / suggest。限定只放在需要的地方，写出具体条件，不用含糊的情态词。**领域规范要求的不确定性表述**（观察性研究不说因果、预实验标明是预实验、置信区间）**不算防御，要保留**；要去掉的是围绕本文贡献本身的免责和稀释。
- **技术来源要直说。** 例如："The proof is a standard X argument; what is new is Y."，或者 "We use the established X assay; what is new is its application to Y." 这比回避更能挡住审稿人"这只是标准结果"的质疑。
- **数值小或代价高的结果，要讲清它约束的是谁。** 把弱点转成操作意义，不要回避。

**自查**：

1. 对新稿跑 `hedge_scan.py`，与 before 和范文分布对比。高于范文范围的类别，逐条处理或写明理由。
2. 逐条对照 ledger 检查过冲：条件结论是否写成了无条件结论；观察性结果是否用了因果措辞（causes、leads to、effect of）；"significant" 是否有对应的检验；law、first、optimal、universal、orders of magnitude、breakthrough 这类词有没有对应的定理、或者带比较对象的数据。
3. 新摘要里每个符号都已定义，或者可以删掉；每个数字都在出处表里。数字较多、或者正文和数据可能不同步时，先跑一遍 `number-audit`。新增的引用用 `cite-verify` 核验。

## Phase 7：盲测编辑（独立子代理）

提示词和流程见 `references/blind-editor-test.md`。

- **Editor test。** 派一个子代理，只给它两个版本的标题、摘要、引言和图 1 图注（原稿和新稿，随机标为 A、B，不告诉它哪个是新稿），外加池 C 的期刊标准。让它扮演目标期刊编辑，限时 5 分钟阅读。对每个版本，它要给出：一句话的主结果、为什么重要、最近的前人工作、送审还是拒稿及理由。最后比较两版哪个更清楚。
- **Overclaim referee。** 另派一个子代理，给它新稿和正文全文，但不给我们的 notes，让它找出所有超出正文支持的句子。
- **核实。** 子代理指出的每个问题，都要在主会话里核实，确认或驳回后再修改。
- **通过标准**：编辑子代理对新稿的一句话复述与 spine 第 1 句一致，overclaim 审查没有经确认成立的问题。不通过就迭代一次；仍不通过，如实报告。
- 需要多个方向的完整审稿（不只是编辑视角和过冲检查）时，用 `mock-review`。

## 最终汇报（中文，简洁）

- 3–5 条结论：最重要的差距是什么，改了什么。
- 产出文件的路径。
- 需要作者确认的改动。
- 只靠重写解决不了的问题（如果有）。
- 盲测结果，标明是推断。
